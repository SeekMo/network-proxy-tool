# Shadowrocket 安全防护测试指南

> 本指南用于验证 `config.conf` 优化后的安全防护是否真正生效。
> 按顺序执行第 1～6 步，每一步都给出了操作方法、预期结果，以及不符合预期时的排查方向。

|   #   | 测试项      | 验证目标                                      |
| :---: | ----------- | --------------------------------------------- |
|   1   | 规则与模块  | 分流规则、HTTPDNS 拦截模块是否按预期工作      |
|   2   | DNS 泄露    | 域名解析是否泄露给运营商或非预期的 DNS 服务商 |
|   3   | WebRTC 泄露 | 网页能否通过 STUN 探测到真实 IP               |
|   4   | IPv6 泄露   | IPv6 流量是否绕过隧道直接出网                 |
|   5   | 通话功能    | 防护措施是否误伤正常的音视频通话              |
|   6   | 日常回归    | 分流是否正确，常用应用是否正常                |

## 一、已知问题

### 1. 规则集会把检测站分到直连，导致测试结果失真

`China_Domain.list` 第 605 行收录了 `.browserleaks.com`，而该规则集的策略是 DIRECT。于是检测页显示的是真实 IP 和本机解析结果，曾被误判为 DNS 泄露。

已在配置中加入下列规则，位置必须在 `China_Domain.list` 之前：

```ini
DOMAIN-SUFFIX,browserleaks.com,兜底线路
DOMAIN-SUFFIX,ipleak.net,兜底线路
DOMAIN-SUFFIX,dnsleaktest.com,兜底线路
DOMAIN-SUFFIX,whoer.net,兜底线路
DOMAIN-SUFFIX,test-ipv6.com,兜底线路
DOMAIN-SUFFIX,ip.sb,兜底线路
DOMAIN-SUFFIX,whatismyip.com,兜底线路
DOMAIN-SUFFIX,myip.la,兜底线路
```

> 💡 以下站点经模拟匹配，目前均落到 `FINAL → 兜底线路`，暂未加规则。**若某天它们显示真实 IP，优先怀疑上游列表把它们收录了**。
> `boce.com` · `ippure.com` · `ipsuper.com` · `ping0.cc` · `cleanip.io` · `ipinfo.io` · `ipjiance.net`

### 2. IPv6 防护尚未得到验证

`ipv6 = false` 只控制是否查询 AAAA 记录，**不代表 IPv6 流量一定被隧道接管**。手册也提到，因 Wi-Fi 接口路由较小，部分流量可能不经过 Shadowrocket。

当前所在网络不提供 IPv6，测试结果无参考价值，需换网络补测。

### 3. HTTPDNS 拦截依赖手动添加模块

配置中的 HTTPDNS 规则集因缺少 `no-resolve` 已停用，改用模块实现。**模块需要在每台设备上手动添加**，手册未说明模块是否随 iCloud 同步。

### 4. 分流模式下存在无法根治的关联风险

网站可以在页面中嵌入一个走直连的资源，从服务端把真实 IP 与你的访问关联起来。这是分流代理的固有特性，只有全局代理能规避。敏感平台的专用配置方案待单独讨论。

### 第 2 步 · DNS 泄露测试

**操作**

1. 打开 https://browserleaks.com/dns
2. **先看页面顶部的 IP**，必须是节点 IP。若是真实 IP，说明该站没走代理，下方结果无效
3. 再看列出的 DNS 服务器

**预期结果**

| 结果                                           | 判定                     |
| ---------------------------------------------- | ------------------------ |
| 仅节点那一侧的解析服务器                       | ✅ 通过                   |
| 出现腾讯、阿里（doh.pub / AliDNS / 223.5.5.5） | ❌ 发生了本地解析，需排查 |
| 出现当前运营商                                 | ❌ 最严重                 |

**不符合时** 　① 查看「日志 / 连接」有无发往国内 DNS 的请求；② 尝试在 `[General]` 增加 `allow-dns-all = false` 后重测。

<br>

### 第 3 步 · WebRTC 泄露测试

**操作**

1. 打开 https://webrtc.github.io/samples/src/content/peerconnection/trickle-ice/
2. 点 **Remove server** 删掉默认服务器
3. 填入一个 STUN 地址 › **Add Server** › **Gather candidates**
4. 查看 **Type 列为 `srflx`** 那一行的 **Address**
5. 删除该服务器，换下一个，重复以上步骤

```
stun:stun.l.google.com:19302
stun:stun.chat.bilibili.com:3478
stun:stun.miwifi.com:3478
```

**预期结果** 　三个地址的 srflx 均为 `stun-response-ip` 所设的值，当前为 `203.0.113.1`。

| srflx 地址        | 判定                                                  |
| ----------------- | ----------------------------------------------------- |
| `203.0.113.1` | ✅ `stun-response-ip` 生效 |
| 真实 IP           | ❌ 泄露                                                |
| 节点 IP           | ⚠️ `stun-response-ip` 未生效，但该路径走了代理，不泄露 |
| 无 srflx，仅 host | STUN 被拦截，不泄露                                   |

**不符合时（方案 B）** 　注释配置中的 `stun-response-ip` 与 `stun-response-ipv6` 两行 › 打开 App「设置 › UDP › 禁用STUN」› 重测。

<br>

1. **先关闭 Shadowrocket**，打开 https://test-ipv6.com ，确认能看到 IPv6 地址，以此证明该网络有 IPv6

| 出现不属于节点的 IPv6 地址        | ❌ IPv6 绕过了隧道 |

## 四、注意事项

### 判定顺序不能颠倒：先确认 IP，再看 DNS

1. 先看检测页顶部的 IP 是不是节点 IP。**若是真实 IP，说明该站没走代理，后面的 DNS 结论一律无效。**
2. IP 正确的前提下，再看解析服务器。

### 「出现腾讯、阿里」是否算泄露，取决于域名本该走哪条路

| 域名类型                   | 解析来源   | 判定                                 |
| -------------------------- | ---------- | ------------------------------------ |
| 国内直连域名（淘宝、京东） | 腾讯、阿里 | ✅ 正常，配置本就如此，可分到就近 CDN |
| 走代理的境外域名           | 节点那一侧 | ✅ 正常，代理域名在远端解析           |
| 走代理的境外域名           | 腾讯、阿里 | ❌ 异常，说明触发了本地解析           |
| 任意域名                   | 当前运营商 | ❌ 最严重                             |

**原理** 　Fake-IP 模式下，App 的 DNS 查询由 Shadowrocket 直接返回 Fake-IP，不产生上游查询；随后按分流规则决定走向——走代理时把**域名**交给节点解析，走直连时才用 `dns-server`（doh.pub、AliDNS）在本机解析。

**例外** 　以下情况本机仍会使用 `dns-server`：

- IP 类规则未带 `no-resolve`
- `always-real-ip` 列表内的域名
- `[Host]` 中带 `server:` 的映射
- 节点域名自身的解析
- 非 A/AAAA 类型的查询，受 `allow-dns-all` 控制
- 全局路由切到「直连」

### 所在地区会影响 DNS 测试结果

主 DNS 是国内的 doh.pub 与 AliDNS。在境外时它们延迟高，**容易超过 2 秒触发备用 DNS**，于是结果里会出现 Cloudflare，这属于预期行为。回到大陆后主 DNS 正常响应，结果会不同，两种情况都正常。

### 解析服务器的 IPv6 地址不是泄露

browserleaks 的 DNS 结果里出现 `2400:cb00::`、`2607:f8b0::`、`2620:171::` 等地址，那是**解析服务器自身的 IPv6**，与你设备的 IPv6 无关。
